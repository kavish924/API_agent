# Spec 05 — Fix generation
Status: Draft · Phase: 3 · PRD v3 ref: FR5 · Depends on: 04-repo-scanning

## Goal
Turn a run's findings into one **minimal** patch that holds the version bump and the
code fixes together. Deterministic tools do as much as they can; a model is used only
for the rest, and everything a model writes must pass an AST guard, because the patch
will run in the repository's own CI.

This spec covers the bump editor, the codemods, the single-shot fixer, the AST guard
and patch assembly. The agent fixer is spec 11 and plugs in as Tier 2.

## User stories
- As a reviewer, I want the smallest possible diff so that I can approve quickly.
- As a developer, I want the fix and the version bump in one change so that neither is
  ever merged without the other.
- As a repo owner, I want a hard limit on what generated code can touch so that an
  injected instruction cannot add arbitrary code to my branch.

## Requirements
| ID | Requirement |
|---|---|
| F5.1 | **Bump editor (deterministic):** rewrite the pinned version of the package in the dependency file that pins it, changing nothing else in the file |
| F5.2 | When the repo has a lock file, the lock is regenerated by the repo's own tool (`uv lock`, `poetry lock`) inside the sandbox install phase (spec 06 F6.14). If that fails, the run has no patch and ends in the issue path |
| F5.3 | **Tier 1, codemods:** deterministic libcst codemods for parameter renames, symbol renames, import path changes and string-literal replacements. Formatting and comments are preserved |
| F5.4 | **Tier 2, model:** for fixable findings no codemod handles. The default is the agent fixer (spec 11). A **single-shot** mode makes one LLM call with the change record, migration hint and enclosing function, and asks for a diff limited to the call site |
| F5.5 | The mode (`agent` or `single-shot`) is a config setting, so the eval can run both on the same findings |
| F5.6 | Findings whose change record has `fixable: false` get no diff. They are passed through as report-only items with their call sites |
| F5.7 | **AST guard, applied to every model-written diff:** comparing the file before and after, every changed statement must either contain a finding or be an import from the watched SDK |
| F5.8 | The guard rejects a diff that adds an import of any other module, touches a file without findings, or touches a non-`.py` file |
| F5.9 | Diff size cap per finding (configurable, default 40 changed lines). Over the cap is a rejection |
| F5.10 | A rejected diff is never partly applied. The rejection reason is returned to the caller (the agent may try again within its budget) |
| F5.11 | Patches apply to the exact commit that was scanned, never a re-read of the branch |
| F5.12 | **Patch assembly:** all accepted fixes and the bump are combined into one patch set. The result records, per finding, `fixed`, `report-only` or `fix-failed` |
| F5.13 | If at least one finding is fixed and others are not, the patch is marked `partial` |
| F5.14 | Each attempt records its tier, the diff, the guard result and the LLM cost |

## Acceptance criteria
- [ ] GIVEN `openai==1.30.0` in `requirements.txt` with a trailing comment, WHEN the bump editor runs, THEN only the version changes and the comment is intact.
- [ ] GIVEN a keyword rename and a call using the old keyword, WHEN the codemod runs, THEN only that argument name changes and the rest of the file is byte-identical.
- [ ] GIVEN an import path change, THEN only the import statement changes.
- [ ] GIVEN a model diff that edits the matched call and also adds `import subprocess`, THEN the guard rejects it.
- [ ] GIVEN a model diff that changes a statement with no finding, THEN the guard rejects it.
- [ ] GIVEN a model diff that edits `.github/workflows/ci.yml` or `pyproject.toml`, THEN the guard rejects it.
- [ ] GIVEN a model diff over the line cap, THEN it is rejected.
- [ ] GIVEN a `response-shape-changed` finding, THEN no diff is produced and the finding is report-only.
- [ ] GIVEN two fixable findings in one file and a bump, THEN one combined patch applies cleanly.
- [ ] GIVEN one fixed and one report-only finding, THEN the patch is marked `partial`.
- [ ] GIVEN the same findings run in `agent` and `single-shot` mode, THEN both produce results in the same shape.

## Technical notes
- The guard works on parsed trees, not on diff text: parse both versions, map changed
  nodes to their enclosing statements, and check each against the set of finding
  statements and SDK imports.
- The bump editor and codemods do not need the guard; they are deterministic and
  covered by tests. The guard exists for model output.
- The dependency file is edited only by the bump editor. A model can never touch it,
  because the guard rejects non-`.py` files.
- The guard narrows what a diff can do. It does not prove a diff harmless: a change
  inside the matched statement could still be wrong. That residual risk is why PRs are
  drafts and why issue-only mode exists (spec 07).
